# Docs Guide: Contributing

How this documentation site is navigated, read and maintained. For the application itself, use [Project Documentation](/docs/).

## Top navigation

The top bar lists four sections: For Everyone, Docs, Pages and Changelog. The Docs Guide is a group inside the Docs sidebar, not a top-level section. The home page opens from the logo, and the GitHub icon opens the Lasuarindo organisation as an external link.

## Sidebars

- **For Everyone** explains the website in everyday language.
- **Docs** holds the technical project documentation, including this guide group.
- **Pages** describes each website page, with both plain and technical notes.
- **Changelog** records what changed.

Sidebar groups are plain section headers. Items sit at the same level as their header, and the current page is highlighted.

## Reading a page

- In **For Everyone**, pages use everyday language and do not mention code, files or settings.
- In **Pages**, a page has a plain part for visitors and a **For maintainers** part with the route, copy bundle and data.
- In **Docs**, pages assume you are working on the project and point to files and configuration.

## Draft labels

When something is marked draft, it is still being prepared. Treat it as an illustration, not as a confirmed fact. This is the single definition used across the docs, so other pages link here instead of repeating it. Draft labels are intentional and should only be removed after the information is confirmed.

## Conventions

- **Two languages.** Translated copy is kept in matching `id`/`en` pairs. A check runs before every build to make sure both sides match.
- **Names and facts.** Proper names are not translated. Numbers and company details come from project data, not guesswork.
- **Where to write.** Simple explanation for visitors → [For Everyone](/for-everyone/). Page explanation with technical notes → [Pages](/pages/). Code and configuration → [Docs](/docs/). What changed → [Changelog](/changelog/).

## Making a change

1. Decide which section the change belongs to.
2. If it adds or edits website copy, update both language files.
3. Run `npm run check:parity` so a missing translation fails early.
4. Run `npm run lint` and `npm run build`.
5. Run `npm run docs:build` to catch broken doc links.
6. Add a short entry to [Changelog](/changelog/) once the change is shipped.

A new website page needs a description in Pages and a simple entry in For Everyone. A new documentation page must be added to its folder's `_meta.json`; a new section also needs `docs/_nav.json`.

Do not invent company facts, dates or numbers. Do not remove a draft label before the information is confirmed. Do not put technical detail into For Everyone.

## Docs-site troubleshooting

- **A docs page does not appear in the sidebar.** Add it to its folder's `_meta.json`. A new section also needs an entry in `docs/_nav.json`; `rspress.config.ts` no longer registers pages.
- **Dark mode uses the wrong colours.** Check the `html.rp-dark` and `html.dark` overrides in `docs/theme.css`.
- **The home page still looks like default Rspress.** The hero and feature cards use separate `--rp-home-*` variables; see [Rspress setup](/docs/guide-setup).
- **Build output is stale.** `doc_build/` is generated by `npm run docs:build` and is gitignored.
